# Codex Decision Router 0.2.1

Плагин распределяет задачи между субагентами Codex с помощью
**Drex Max (`nace-ai/drex-max`)**, основной модели принятия решений.
**Jev 1.14 (`typesafe/jev-1.14`)** — резерв при ошибке, повреждённом ответе
или неуверенном выборе Drex. Резерв получает только спорные вопросы.

OpenRouter оплачивает маршрутизацию. Исполнителей запускает основной агент
через штатные инструменты Codex в режиме текущего аккаунта. Основная модель
составляет задачи, маршрутизатор выбирает подходящие профили, затем Codex
исполняет задачи по зависимостям и проверяет результат.

## Claude Code: распределение субагентов Claude и Codex

Кроме Codex, роутер подключается к Claude Code. Основная модель сессии делит
задачу, роутер выбирает для каждой части модель и effort из 9 профилей
(Haiku, Sonnet, Opus и Codex: Luna, Terra, Sol, Astra), а OpenRouter оплачивает
только выбор. Запуск Codex делает `scripts/run_codex_task.py`. Установка:

```bash
python3 scripts/install_claude_code.py
```

Скрипт копирует навык в `~/.claude/skills/route-subagents` с путями этой папки
и регистрирует MCP-сервер `decision-router`. Остальные шаги (ключ, разрешения,
вставка `claude-code/CLAUDE-snippet.md` в `~/.claude/CLAUDE.md`) он печатает в
конце. Профили лежат в `claude-code/skills/route-subagents/profiles.json`,
таблица допустимых вариантов по типам задач — в `SKILL.md` рядом.
Подробности и ограничения: [решение 001](docs/decisions/001-claude-code-host.md).
Экономия на реальных задачах не измерена.

## Куда добавить ключ

Запустите в **Терминале**:

```bash
python3 /Users/habib/Documents/N8N/jev-codex-router/scripts/setup_key.py
```

Вставьте ключ OpenRouter в скрытый запрос. Он сохранится отдельно от плагина:

```text
/Users/habib/.config/codex-decision-router/credentials.json
```

Файл имеет права 0600. Его формат для ручного редактирования:

```json
{"OPENROUTER_API_KEY": "вставьте_свой_ключ_OpenRouter"}
```

Ключ не нужен в чате, исходниках или манифесте плагина. После сохранения
следующий вызов маршрутизатора подхватит его без перезапуска MCP.
При наличии `OPENROUTER_API_KEY` в окружении приоритет имеет окружение.
`CODEX_DECISION_ROUTER_KEY_FILE` позволяет явно задать другой файл.

Проверить состояние без показа ключа:

```bash
python3 /Users/habib/Documents/N8N/jev-codex-router/scripts/setup_key.py --status
```

## Как пользоваться

Достаточно отправить одно упоминание навыка:

```text
$jev-codex-router:route-subagents
```

Инструкция по распределению уже содержится в навыке и подгружается агенту.
Он применит её к последней незавершённой задаче в переписке. Если задачи ещё
нет, он сообщит о готовности и применит маршрутизацию к следующему заданию.
Дописывать «используй плагин» или повторять настройки не нужно.

Основной агент получит доступные модели,
составит подзадачи, вызовет `route_tasks`, применит выбранные модели и уровни
рассуждения к штатным субагентам, а затем соберёт результат.

Три MCP-инструмента: `router_status`, `preview_routing`, `route_tasks`.
`preview_routing` проверяет вход и показывает будущий запрос без обращения
к API. В штатном режиме отдельный preview на каждый запрос не нужен.

Плагин вызывается явно и не перехватывает все сообщения. Он не читает остаток
лимита подписки и не переключает модель главного чата. Доступность моделей,
права на инструменты и применение плана контролирует Codex.

## Переход на резерв

1. Один запрос Drex Max для всех задач, где есть выбор профиля.
2. Один запрос Jev 1.14 только для оставшихся спорных задач.
3. Если оба варианта не дали надёжного решения — заранее указанный профиль
   задачи, с явным статусом `fallback_plan`.

Ошибки ключа, оплаты или доступа аккаунта (401/402/403) останавливают цепочку.
Повторного обращения к той же модели и бесконечных повторов нет.
Каждый запрос ограничен 12 секундами; максимум две попытки на распределение.
Кэш успешных решений действует 10 минут в памяти MCP-процесса.
Допускается до 32 API-вызовов за жизнь процесса; это не денежный лимит.
В `attempts` видны модели, причины перехода, токены и стоимость каждой попытки.
Стоимость таймаута может быть неизвестна, поэтому сумма тогда обозначена null.

Порог вероятности по умолчанию 0.7, отрыв от следующего варианта 0.15.
Это стартовые параметры, не гарантия качества; их нужно оценивать на задачах
пользователя. Для каждой задачи хост ограничивает `allowed_profiles`
достаточными моделями и выбирает достаточный `fallback_profile`.

## Проверка

Python 3.10+, сторонние зависимости не нужны.

```bash
python3 -m unittest discover -s tests -v
python3 server/main.py status
python3 server/main.py preview < examples/architecture-code-research.json
```

После добавления ключа можно выполнить один платный синтетический вызов:

```bash
python3 server/main.py route < examples/architecture-code-research.json
```

Команда возвращает план, сама исполнителей не запускает. Код возврата: 0 —
план выбран моделями; 2 — есть заранее заданные резервные профили; 1 — ошибка
входа. Пример моделей относится к исходному чату; в другом чате хост должен
заново проверить их доступность. `cost_rank` задаёт относительное предпочтение,
не тариф или коэффициент расхода подписки.
